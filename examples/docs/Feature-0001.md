# 1. Контекст бизнес-задачи

Нужно сделать quality gate для сотен markdown документов: проверять шаблон, метаданные и критичные секции.
Сейчас доки живут своей жизнью: устаревают, плохо ищутся и в итоге люди задают одни и те же вопросы.
Цель: инженерный воспроизводимый контур, где policy правят аналитики, а engine стабилен и гоняется в CI.

# 2 Требования

- CLI: doc-quality run --paths / --paths-file ...
- Отчёты: JSON на файл + summary.json
- Fail если есть blocker, warn если только предупреждения.
- Политики и шаблоны лежат в .docq/

# 3. Нефункциональные требования

Нужно чтобы запуск работал за разумное время, корректно обрабатывал файлы с русским текстом и не падал на датах.
LLM часть должна быть опциональной: без ключа запускается rules-only режим.
